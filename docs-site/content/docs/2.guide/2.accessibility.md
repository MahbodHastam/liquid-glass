---
title: Accessibility
description: What the library does for you when users change their settings, and what's left to you.
---

You don't have to configure any of this. It reacts to the user's settings as they change, without a reload.

| User setting | What happens |
|---|---|
| `prefers-reduced-motion: reduce` | The glass stays, but refraction drops to 35% of its value, zoom drops to 1 and the pointer highlight is off. There is no animation loop in any case. |
| `reducedMotion="fallback"` and reduce | The CSS fallback is used instead of the shader. |
| `reducedMotion="static"` | Always behaves as if reduce were set. |
| `reducedMotion="ignore"` | Ignores the setting. Not recommended. |
| `prefers-reduced-transparency: reduce` | A solid surface, never glass. |
| `prefers-contrast: more`, `forced-colors: active` | A solid `Canvas` / `CanvasText` surface with a visible border, never glass. |
| Save-Data | `auto` quality starts at `low`, and snapshots are skipped unless you set `ignoreSaveData`. |

## Screen readers and keyboards

The canvas is purely decorative. It has `aria-hidden="true"` and `pointer-events: none`, and it can't take focus. Whatever you put inside the lens is ordinary DOM, so it can be selected and focused, and screen readers read it as normal.

## Legibility is your responsibility

Glass over an arbitrary backdrop can't promise enough contrast, because the library doesn't know what will end up behind your text. If the lens holds body text, make the tint opaque enough that the text meets WCAG AA (4.5:1) against the worst case behind it. White text on `tint="rgb(15 23 42 / 0.55)"` is a reasonable start, and so is dark text on `tint="rgb(255 255 255 / 0.7)"`. Then check it with a contrast tool against your real backdrop.
