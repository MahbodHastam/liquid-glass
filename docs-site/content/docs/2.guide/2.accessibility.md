These work with no configuration and react to runtime changes.

| User preference | Behaviour |
|---|---|
| `prefers-reduced-motion: reduce` | Still glass, but refraction ×0.35, zoom → 1, no pointer tracking. No animation loop ever runs. |
| `reducedMotion="fallback"` + reduce | CSS fallback instead |
| `reducedMotion="static"` | Always behave as reduced |
| `reducedMotion="ignore"` | Opt out (discouraged) |
| `prefers-reduced-transparency: reduce` | Opaque surface, never glass |
| `prefers-contrast: more`, `forced-colors: active` | Opaque `Canvas`/`CanvasText` surface with a visible border, never glass |
| Save-Data | `auto` quality starts at `low`; snapshot backdrops aren't captured unless `ignoreSaveData` |

The canvas is decorative: `aria-hidden="true"`, `pointer-events: none`, not focusable. Slot content stays real DOM, so it is selectable and focusable and screen readers read it.

## Legibility is your responsibility

Glass over an arbitrary backdrop can't guarantee contrast. For body text, give the tint enough opacity that text meets WCAG AA (4.5:1) against the worst case behind it, for example white text on `tint="rgb(15 23 42 / 0.55)"` or dark text on `tint="rgb(255 255 255 / 0.7)"`. Check with a contrast tool against your real backdrop.
