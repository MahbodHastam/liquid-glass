---
title: Backdrops
description: Media vs snapshot sources, and their limits.
---

WebGL can't read the pixels behind a canvas, so each lens needs a source to refract.

| Source | Use it for | Cost |
|---|---|---|
| **Media**: `:source="imgRef"` (`<img>`, `<video>`, `<canvas>`) | Heroes, cards over photos, video backgrounds | Near zero. No DOM capture. Video updates once per video frame. Honours `object-fit` / `object-position`. |
| **Snapshot**: wrap content in `<LiquidGlassBackdrop>` | Glass over arbitrary HTML, e.g. a sticky navbar over page content | One capture on mount, then again on resize, font load, image load or `refresh()`. Scrolling never re-captures. |

```vue
<LiquidGlassBackdrop>
  <LiquidGlass class="sticky top-2 h-14 rounded-2xl">Nav</LiquidGlass>
  <article>…page content…</article>
</LiquidGlassBackdrop>
```

## `<LiquidGlassBackdrop>` props

- `observe`: re-capture on DOM mutations, debounced. Default off.
- `captureScale`: default `0.5`; the blur hides the downscale. Raise it (up to `1`) when lenses magnify or refract text.
- `embedFonts`, `ignoreSaveData`, `capture`.

It exposes `refresh()`.

## Snapshot limitations

::warning
Snapshots rasterise with snapDOM (SVG `foreignObject`), so they are never pixel-perfect.
::

- Cross-origin images without CORS, iframes and some exotic CSS are not captured.
- Content that changes all the time (carousels, counters) needs `observe` or a manual `refresh()`.
- The whole backdrop is one texture, so capture size is capped by the GPU's max texture size and a 16 MP canvas limit. Very tall containers are captured at less than the requested scale.
- Prefer the media source whenever the backdrop is an image or video.

Cross-origin media must be CORS-enabled (`crossorigin="anonymous"` plus an `Access-Control-Allow-Origin` header). Otherwise that lens falls back to CSS and you get one dev-mode warning.
